When I joined Reloadly, developer experience had little structure: a few SDKs, a Postman collection, and an API reference hardcoded in HTML.

## Rebuilding the developer docs

I started by revamping the developer documentation. After running developer surveys and weighing my team's budget, I chose a collaborative, open source workflow built on GitBook. I built it from scratch, and within my first six months both the engineering and product teams were contributing to the docs.

Over two years I built several iterations of the documentation with GitBook, ReadMe, and Redocly. The latest iteration of the developer documentation launched in September 2022.

- I wrote product docs and API references for two products from scratch, in Markdown and YAML.
- I documented Reloadly's SDKs from scratch and wrote guides on integrating them into existing applications.
- I set up analytics to track developer searches and a satisfaction index on the docs site, then adapted the docs to that feedback.
- I set up and managed the CI/CD pipeline for the developer docs on Bitbucket, which shortened time-to-market for new product features.
- I worked with the product team to turn developer feedback into product features.

## A Postman collection customers could use

I noticed a gap in how customers tested our APIs. I collected the Postman collections that the support and solutions teams already had, revamped them, split the requests into live and sandbox modes, organised them, and published the result.

## Developer community

I organised live workshops with developer advocates from other companies, ran a product hackathon, and built a Slack community forum for onboarding, developer feedback, and support.
